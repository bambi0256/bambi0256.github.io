# Vision — B.Bee 블로그

## 한 줄 목표

GitHub Pages 위에서 동작하는 **개인 블로그 겸 포트폴리오**. 블로그 주인이 웹에서 직접 글을 쓰고 게시하며, 방문자는 최근 글을 목록으로 빠르게 훑을 수 있다. 모바일에서도 쓸 수 있는 **내용이 비어 있는 상태의 블로그**에서 시작한다.

## 원칙

- **버전 단위로 종결**: 각 버전의 범위를 구현하면 그 버전을 종결한다. 범위를 넓히지 않는다.
- **범위 밖 제안은 승인제**: 범위 밖 개선 아이디어는 구현하지 않는다. 사용자에게 기능과 이유를 설명하고, **승인받은 뒤에만** 추가한다. (제안 방식은 CLAUDE.md 참고)
- **정적 호스팅 유지**: GitHub Pages(정적)를 전제로 한다. 별도 서버 운영이 필요한 설계는 사용자 승인 없이 도입하지 않는다.
- **블로그 주인 = 단일 사용자**: 다중 사용자, 댓글, 회원 시스템은 범위 밖이다.

## 버전

|---|---|---|
| v1.0 (MVP) | ✅ 종결 | 리팩토링, 주인 검증, 웹 글 작성 툴(+이미지 업로드) |

| 보류 | ⏸ | 방문자 인사이트 페이지 ([D-002](decisions.md)) |

## v1.0 요약 (종결)

결정 기록은 [decisions.md](decisions.md) D-001~D-014.

1. **리팩토링**: 소스(`templates/`, `mdposts/`, `assets/`)와 생성물(`index.html`, `about/`, `projects/`, `write/`, `json/`) 경계 정리, 미사용 JS 제거, 빌드 경로 상수화(`assets/py/config.py`).
2. **주인 검증**: Fine-grained PAT → GitHub API로 계정(`bambi0256`)과 토큰의 쓰기 권한 확인. 토큰은 `sessionStorage`에만 보관.
3. **글 작성 툴** (`/write/`): Front Matter 폼, Markdown 미리보기, 이미지 업로드(게시물 단위 폴더), Git Data API로 글+이미지를 한 커밋에 게시.

## v1.1 범위

### 1. 자동 빌드·배포 조건 변경

**목표**: 불필요한 자동 실행을 없앤다. 자동 빌드·배포는 **새 글이 게시될 때**와 **수동 실행**으로만 시작한다. ([D-015](decisions.md))

완료 기준:
- [x] 워크플로우 트리거가 `mdposts/**` push(새 글 게시)와 `workflow_dispatch`(수동 실행)로 한정됨
- [x] 템플릿·스크립트·CSS·JS 변경 push로는 워크플로우가 실행되지 않음
- [x] README·CLAUDE.md의 배포 설명이 새 조건과 일치 (템플릿/스크립트 수정 시 로컬 빌드 후 생성물 커밋 또는 수동 실행)

### 2. 디자인 개편: 카드형 → 목록형

공통 방향: 기존 이미지 카드(`post-card`)를 없애고, **제목 · 작성일 · 내용 앞부분**으로 구성된 목록형으로 바꾼다. 배경은 어두운 색(`#343434`), 글자는 노란색(`#FFDE59`) 기조를 유지한다. 해석 사항은 [D-016](decisions.md) 참고.

#### 2-1. Projects 페이지
- 포스트는 `Projects/[Project]/[Post]` 구조이므로 **[Project] 단위 탭**으로 나눈다.
- 탭은 **가장 최근에 작성된 포스트가 있는 프로젝트 순**으로 나열한다.
- 각 탭은 해당 프로젝트의 **최근 포스트 3개**를 목록형으로 노출한다.
- 탭 **우측의 Learn More 버튼**으로 해당 프로젝트 페이지(`/projects/<project>/`)로 이동한다.
- 목록 항목은 제목, 작성일, 내용 앞부분을 포함하고 **대표 이미지는 표시하지 않는다**.

#### 2-2. Home 페이지
- 전체 프로젝트 통틀어 **가장 최근에 업데이트된 포스트 3개**를 목록형으로 노출한다.

#### 2-3. 프로젝트 페이지(`/projects/<project>/`)
- 같은 목록형 컴포넌트로 전체 포스트를 노출한다(페이지네이션 유지). *(카드형 CSS 제거에 따른 일관성 확보)*

#### 2-4. CSS 정리
- 카드형 관련 CSS(`.post-card`, `.post-grid`, `.card-text` 등)를 제거한다.
- 영역 컨테이너 관련 CSS를 재조정해 목록형 기준으로 통일한다. (중복되던 `index-style.css`/`project-style.css`의 공통 부분은 하나로 합친다.)

#### 2-5. Write 페이지
- UI 텍스트(제목, 설명, 라벨, 안내문 등)를 사이트 전체의 노란색(`#FFDE59`)으로 통일한다. 어두운 배경에서 읽히지 않는 글자색을 없앤다.

완료 기준:
- [x] Projects: 프로젝트 탭(최근 포스트 순), 탭당 최근 3개 목록, 탭 우측 Learn More, 이미지 없음
- [x] Home: 최근 포스트 3개 목록
- [x] 프로젝트 페이지: 목록형
- [x] 카드형 CSS 제거, 컨테이너 CSS 정리 (미사용 규칙 없음)
- [x] Write 페이지 텍스트가 모두 어두운 배경에서 읽힘
- [x] **시각 확인**: 데스크톱·모바일 폭에서 Home / Projects / 프로젝트 / Write(로그인 전·후) / Post / About 스크린샷을 직접 확인함

> 디자인 작업 규칙: 작업 전 현재 CSS·HTML을 모두 읽어 구성을 파악하고, 완료 전 반드시 시각 확인을 거친다. (CLAUDE.md "디자인 작업 절차" 참고)

## v1.2 범위 — 사용 가능한 빈 블로그

**목표**: 기존 포스트·프로젝트를 모두 걷어내고, 구조가 정리되어 있고 모바일에서도 보이는 **빈 블로그**를 만든다. 빈 상태에서 바로 첫 글을 쓸 수 있어야 한다. ([D-018~D-021](decisions.md))

### 1. 이미지 디렉토리 정리
- `assets/image/` 의 이미지를 용도별 디렉토리로 옮기고 참조를 모두 고친다.
  - `common/` — 로고, 소셜 아이콘 (헤더·푸터)
  - `home/` — Home Intro 이미지
  - `about/` — About 페이지 이미지(프로필 포함)
  - `blog/<주제>/` — 글에 쓰던 이미지 (현재 참조 없음)
- 게시물 이미지는 계속 `mdposts/<project>/<slug>/` 에 글과 함께 둔다.

### 2. 콘텐츠 비우기
- 기존 포스트·프로젝트(`mdposts/*`, `projects/<project>/`, `json/*-posts.json`, 설정의 프로젝트 항목)를 모두 제거한다.
- 빈 상태에서도 빌드가 성공하고, Home/Projects 가 빈 상태 문구를 보여준다. (`mdposts/` 는 `.gitkeep` 으로 유지)

### 3. 빈 블로그에서 첫 글 작성
- 프로젝트가 하나도 없어도 작성 툴에서 **새 프로젝트를 만들며 첫 글을 게시**할 수 있다. (프로젝트 slug·이름·설명 입력)
- 프로젝트 이름·설명은 글의 Front Matter(`project_title`, `project_description`)에 기록되고, 빌드가 파일 순서와 무관하게 읽는다.

### 4. 모바일 대응
- 모든 페이지(Home, Projects, 프로젝트, Post, About, Write)가 390px 폭에서 가로 스크롤·잘림 없이 읽힌다.
- 헤더(햄버거 · 로고 · 아이콘 한 줄), Home Intro, About, Post(목차를 본문 위로, 표·코드 블록 가로 스크롤), Write 규격을 조정한다.
- 부수 수정: 빌드에 Markdown `tables` 확장을 추가해 표가 렌더링되도록 한다(작성 툴 미리보기와 결과 일치).

완료 기준:
- [x] 이미지가 용도별 디렉토리에 있고 깨진 참조가 없음
- [x] 기존 포스트·프로젝트·관련 JSON 제거, 빈 상태 빌드 성공
- [x] 빈 블로그에서 새 프로젝트로 첫 글을 게시하는 흐름이 동작 (모의 API 검증)
- [x] 390px(모바일) / 768px(태블릿) / 1400px(데스크톱)에서 시각 확인
- [ ] 사용자 확인: 실제 GitHub 에서 첫 글 게시 후 사이트 반영

## 범위 밖 (명시적으로 하지 않음)

댓글, 검색, 다크/라이트 전환, 태그 페이지, RSS, 다국어, SEO 확장, 위 범위 외 디자인 개편, 프레임워크·번들러 도입, 글 수정/삭제 UI, 이미지 리사이즈, 방문자 인사이트(보류), 새 프로젝트 외의 프로젝트 정보(이름·설명) 수정 UI.
→ 필요하다고 판단되면 **구현하지 말고 제안**한다.
